## 更新日: 2026-03-19

## 1. 企画概要

### 2冊構成

| | Book A | Book B |
|---|--------|--------|
| **テーマ** | ビジネスパーソン向けゲーム理論入門 | IT現場の構造分析 |
| **市場** | 広い市場（一般ビジネス） | 深い市場（ITエンジニア・PM） |
| **ゲーム理論の位置づけ** | 主役（思考ツールとして紹介） | 分析ツールの一つ（組織論・行動経済学と併用） |
| **出版順** | 先行（市場テスト） | 後発（送客を受ける深掘り本） |
| **分量** | コンパクト | 厚め |

### 著者プロフィール
- 地方IT企業でR&Dチームマネージャー兼エンジニア（経験約20年）
- 介護・福祉ドメインのソフトウェア開発が本業
- KDP技術書を複数出版（Claude Code本がヒット実績）
- SIer多重下請け構造、パーキンソンの法則など、日本のIT業界の構造問題に独自の分析視点
- 出版方針：「Why over How」（ハウツーよりも構造理解を重視）
- 差別化原則：「同じ食材、違う料理」（既存情報の再構成で独自の切り口）
- ゲーム理論は現時点でゼロからの学習段階

## 2. Book A：ビジネスパーソン向けゲーム理論入門

### コンセプト
ゲーム理論を「日常やビジネスの意思決定に使える思考ツール」として紹介する入門書。
数式は最小限にし、身近な具体例で直感的に理解できることを目指す。

### 想定テーマ候補
- 交渉術（給与交渉、取引先との価格交渉）
- 社内政治の構造（なぜ会議で本音が出ないのか）
- 転職・キャリアの意思決定
- 副業・複業の戦略
- 価格競争と差別化
- 日常の駆け引き（家庭内の家事分担、子どもとの交渉など）

### 狙い
- 検索ボリュームのあるキーワード（交渉、転職、副業など）と組み合わせてリーチを広げる
- 比較的コンパクトに仕上げ、先行出版して市場反応をテスト
- Book Bへの送客導線を設計

---

## 3. Book B：IT現場の構造分析

### コンセプト
「なぜITプロジェクトは構造的に失敗するのか」を、ゲーム理論・組織論・行動経済学などの
複数フレームワークで分析する本。ゲーム理論は分析ツールの一つとして位置づけ。

### 想定テーマ候補
- 見積もり崩壊と情報の非対称性（レモン市場）
- 技術的負債と共有地の悲劇
- 多重下請け構造とプリンシパル＝エージェント問題
- CI/CD・新技術導入が進まない「ナッシュ均衡の罠」
- 「誰も責任を取らない」構造のゲーム理論的説明
- なぜ日本のSIerは非効率なまま存続するのか
- パーキンソンの法則とインセンティブ設計

### 狙い
- 20年の現場経験がないと書けない「AIにコモディタイズされない」コンテンツ
- 読者に「あー、うちの現場のあれ、そういう構造だったのか」という腹落ち体験を提供
- Book Aからの送客を受ける深掘り本
