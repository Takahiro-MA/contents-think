# カジュアルライン 品質ゲート

> 目的: 著者の感覚に頼らず、著者に渡す前にこちらで品質を数字で担保する。
> 置き場所: `process.md` の F工程（著者レビューの反復）の直前。合格しないうちは著者にEPUBを渡さない。
> 基準の本: C01『AIの始め方、これだけでOK』（著者が品質OKと判断して出版した本）。閾値と合格線はC01の実測から決めた（2026-09-29）。

## 3つの層

| 層 | 何を見るか | 道具 | 出力 |
|---|---|---|---|
| 第1層 機械チェック | 形式・文体・AIっぽさ・参照・数字・禁止語・字数 | `gate.py` ＋ `gate-config.yaml` | `<book>/quality/gate-report.md` |
| 第2層 読者評価 | 対象読者の目で7項目×5点 | `rubric.md`（ペルソナ3人がサブエージェントで通読・採点） | `<book>/quality/rubric-score.md` |
| 第3層 答え合わせ | 著者レビューの指摘の件数と種類。ゲートが見落としたものを見つける | `author-feedback-log.md` | 同ファイル |

- 第1層は数えられるものだけを数える。読後の満足・信頼・分かりやすさは第2層で見る
- 第3層は合否を決めない。第1層・第2層の基準を更新するための記録

## 使い方

```bash
cd contents-think/CLI/workspace/casual-line/quality-gate

# 第1層（C02の例。事実パックとhubを照合先に渡す）
python3 gate.py ../../../../../kindle2/C02_kintore-50s \
  --facts ../notes/2026-09-29-c02-factpack.md --facts ../c02-kintore-50s/thinking-hub.md

# 出版前として判定する（図の仮枠・出所不明の数字も合否に入れる）
python3 gate.py ../../../../../kindle2/C02_kintore-50s --stage publish --facts ...

# テスト
uvx --with pyyaml pytest -q test_gate.py -p no:cacheprovider
```

- 主なオプション: `--facts`（複数可）／`--stage draft|publish`／`--banned 語`（使わない言葉の追加、複数可）／`--exclude-quotes`（禁止語の判定で「」内を除く）／`--skip-epubcheck`／`--out`
- 本ごとの閾値・使わない言葉・段階は `gate-config.yaml` の `books.<フォルダ名>` に書く
- 不合格があると終了コード1。明細（該当箇所の `ファイル:行`）はレポートの「明細」節
- epubcheck は `release/` の中で最も新しいEPUBにかける。先に `build/build_epub.py` でビルドしておく
- 第2層は、書き手とは別のサブエージェント（Opus）に `rubric.md` を渡し、ペルソナごとに全文を通読させて採点させる。ペルソナはhubの2節（無い本はコンセプトの対象読者から3人）

### 測り方の決まり（gate.py）

- 慰め・許可の言葉、「AではなくB」「のです」「つまり」「むしろ」、断り書きは、**書き手の地の文だけ**を数える（「」内の引用・例文・AIの返事の実録は除く）
- 断り書きは表の中を数えない。表の出典欄は断り書きを集約する正しい置き場所（`writing-checklist.md` 4.）
- 「のです」は「ものです」を除く。「十分（じゅうぶん）」は数字として扱わない
- 数字の照合: 本文の数字（単位つき・範囲・漢数字）を、事実ファイルに「数字＋単位」で出てくるかで判定する。数値だけ一致は「要目視」、どちらも無いものが「出所不明」。第N章・図N-N・段N は番号なので外す。計算で出した数字（例: 12週間→84日）も出所不明に出るので、目視で確認する
- 1文段落で節を終える箇所は、40字以下のものだけを決め台詞の候補として数える

## 合格の定義

著者に渡してよいのは、次の2つを両方満たしたとき。

1. **第1層**: `gate.py` の判定が全項目「合格」（「参考」は合否に入れない。ただし出版前 `--stage publish` では図の仮枠・出所不明の数字も合否に入る）
2. **第2層**: 3人の平均で、次の3つをすべて満たす
   - 合計 **24.0点以上**（35点満点。C01の26.0点 − 2点）
   - どの項目も **3.0以上**
   - 項目5「信頼」が **3.3以上**（C01の点。余裕を見ない）

合格線を変えるときはこの節だけを直す（`rubric.md` には決め方だけを書いてある）。

### C01で不合格になった項目の判断

- **「第N章」1章の最多（第9章に11回）**: 閾値ではなくC01に残っている問題と判断した。第9章は約1,800字で、他の章への参照が文ごとに出る（`09-ch09.md:7,11,35,53,57,65,69,87`）。第2層の採点者も独立に「第9章の章参照を減らす」を挙げた。出版後の改訂候補。閾値は8のまま
- **数字（参考表示）**: C01の照合先 `factcheck-2026-09-28.md` は検証済み項目の表で、使ってよい数字の一覧ではないため、C01では合否に入れていない（`gate-config.yaml`）。出所不明に出た7件のうち、本が自分で決めた数字（10分）・AIの返事の実録・例文の数字を除くと、`01-ch01.md:25,41`「五十代から上では、まだ半分前後の人が一度も使っていません」だけが要確認。出典（日本リサーチセンター）には二十代69%・六十代37%しか無く、五十代の数字は書かれていない

## ゲートの更新手順（見落としが出たとき）

著者レビューで指摘が出たら、`author-feedback-log.md` に分類して記録し、各指摘について次を順に判断する。

1. **第1層で数えられるか**（決まった言い回し・形式・参照の誤り）→ `gate.py` に項目を足すか、`gate-config.yaml` のパターン・禁止語に追加する。追加したら `test_gate.py` にテストを足し、C01とその本に再実行して、C01が不合格にならないか（なるならC01にも同じ問題があるか）を確かめる
2. **第2層の基準で減点されるはずだったか** → されなかったなら、`rubric.md` の該当項目の点ごとの基準に、その指摘を具体例として書き足す（「〜があれば4点以下」）
3. **どちらでも拾えない**（事実の古さ、著者の体験）→ ゲートではなく工程（H工程の事実照合、体験記述の一覧化）で扱う。`process.md` か `writing-checklist.md` に追記する
4. 同じ種類の指摘が2冊続けて出たら、その種類の閾値を厳しくするか、合格線を上げる（「合格の定義」を直す）
5. 閾値を変えたら、この README の「閾値の根拠」表を更新する。数値を書くのは `gate-config.yaml` と、この表の根拠欄だけにする
