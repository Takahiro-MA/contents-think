# 第2層: 読者評価の採点表（rubric）

> 目的: 著者に渡す前に、対象読者の目で「買ってよかったか」を点数にする。第1層（`gate.py`）が測れない、読後の満足と信頼を見る。
> 基準の本: C01『AIの始め方、これだけでOK』（著者が品質OKと判断して出版した本）。合格線はC01の点数から決める（下の「合格線」）。

---

## 採点の手順

1. **ペルソナを3人立てる**。hub（`c<NN>-<slug>/thinking-hub.md` の2節）に想定読者があればそれを使う。無い本（C01）はコンセプトの「ターゲット読者」から、現在地の違う3人を立てる（例: 未経験／一度試してやめた／周りに急かされている）
2. **ペルソナごとに本文を最初から最後まで通読する**（`epub/*.md` を章リスト順に。拾い読みで採点しない）。読みながら、そのペルソナが「ここで止まる」「ここで得をした」と感じた箇所を `ファイル:行` で控える
3. **7項目を各5点で採点**し、各項目に根拠（本文の箇所か引用）を1つ以上つける。根拠のない点数は無効
4. 3人の点数を項目ごとに平均し、合計（35点満点）と最低項目を出す
5. 結果を `<book>/quality/rubric-score.md` に書く。書式: ペルソナ紹介 → ペルソナ別の採点表（点・根拠） → 平均表 → 直すべき点（点数を下げた箇所を優先度順に）

- 採点者は書き手と別のエージェントにする（自分の書いた原稿を採点しない）
- 同じ本を再採点するときは、前回の点と比べて上下した項目と理由を書く
- 迷ったら低いほうをつける。3点が「普通に出せる」、4点が「C01並み」、5点は「この項目は直すところが見当たらない」

---

## 採点項目と基準

### 1. 対象読者に合っているか（的）

| 点 | 基準 |
|---|---|
| 5 | 冒頭で「誰向け・誰には物足りないか」が明記され、全章がこのペルソナの現在地から話している。置いていかれる箇所も、分かりきった話で退屈する箇所もない |
| 4 | 対象の明記があり、ほぼ全章が合っている。1〜2か所、このペルソナには易しすぎる／難しすぎる箇所がある |
| 3 | 対象は分かるが、章によって想定読者がぶれる（初心者向けの章と経験者向けの章が混ざる） |
| 2 | 対象の明記がない、または明記と中身がずれている。このペルソナには半分ほどが的外れ |
| 1 | このペルソナが読む本ではない |

### 2. 最初の一回をやれそうか（実践）

| 点 | 基準 |
|---|---|
| 5 | 読み終えた日に、本を横に置いたまま最初の一回ができる。用意するもの・手順・終わりの判断（ここまでやれば終わり）が具体的で、迷う分岐がない |
| 4 | 最初の一回ができる。1か所、「ここはどうするの」と止まる箇所があるが、本文のどこかに答えがある |
| 3 | やり方は分かるが、手順が散らばっていて読み返しが要る。または終わりの判断が曖昧 |
| 2 | 何をするかは分かるが、具体的な手順・画面・数字が足りず、自分では始められない |
| 1 | 心構えの本で、実践の手順がない |

### 3. 読後に得をしたと思えるか（300円の価値）

| 点 | 基準 |
|---|---|
| 5 | 「300円なら安い」。ネットの無料記事では手に入らない、まとまった手順・判断基準・続け方が手元に残る。読み返す場所（表・チェックリスト等）がある |
| 4 | 払った分は取れた。新しく知ったことと、この先の続け方が1つ以上ある |
| 3 | 損はしていないが、検索で集めた情報とあまり変わらない |
| 2 | 知っていることが大半。水増しの章・繰り返しが目立つ |
| 1 | 返品したい |

### 4. 分かりやすさ（専門用語・説明の順）

| 点 | 基準 |
|---|---|
| 5 | 専門用語は初出で言い換えられ、説明は「何を→なぜ→どうやって」の順。前の章を読み返さずに各章が読める。例と箇条書きが適所にある |
| 4 | 1〜2か所、言い換えのない言葉か、順番が前後する説明がある |
| 3 | 言い換えのない専門用語が3か所以上、または「第N章で」の参照が多くて行き来が要る |
| 2 | 説明の順番が崩れていて、読み返さないと分からない章がある |
| 1 | このペルソナには読めない |

### 5. 信頼できるか（根拠・誠実さ）

| 点 | 基準 |
|---|---|
| 5 | 数字や仕様に出所があり、分からないことは分からないと書いている。約束が本文で守られている（タイトル・まえがきの約束を回収）。体験の作り話がない |
| 4 | 根拠は示されているが、出所の見えない言い切りが1〜2か所ある |
| 3 | 出所の分からない数字・言い切りが3か所以上。または根拠の示し方がくどく、かえって読みにくい |
| 2 | 約束と中身がずれている（タイトルの約束を本文が回収しない）、または古い・誤った情報がある |
| 1 | 信用できない（誤り・誇張・作り話） |

### 6. 怖がらせすぎ・説教くさくないか（トーン）

| 点 | 基準 |
|---|---|
| 5 | 注意は必要な箇所に、実態に合った重さで書かれている。読者を責める・諭す言い回しがない。読後に「やってみよう」が残る |
| 4 | 1〜2か所、注意が重い／言い聞かせる調子の箇所がある |
| 3 | 注意書き・断り書きが目立ち、始める前に気が重くなる章がある。または「〜しましょう」の指図が続く |
| 2 | 読むと怖くなる、または叱られている気分になる |
| 1 | 読者を不安にさせて終わる |

### 7. AIっぽさを感じないか（文章の人間らしさ）

| 点 | 基準 |
|---|---|
| 5 | 一人の書き手が読者に向けて書いた文章に読める。決め台詞・慰めの連発・同じ型の書き出しに気づかない |
| 4 | 通読して1〜2か所、「AIっぽい」と引っかかる（決め台詞・過剰に優しい語りかけ・同じ言い回しの反復） |
| 3 | 気になる箇所が3〜5か所。または規程集・仕様書のような硬さ（断り書き・出典の前置き・章参照の同形反復）が章をまたいで続く |
| 2 | 章ごとに同じ型が繰り返され、機械的に作られた印象が残る |
| 1 | 明らかにAIの文章 |

---

## 合格線の決め方

1. 基準の本（C01）を同じ手順で採点し、平均の合計（35点満点）と各項目の平均を記録する
2. **合格線 = 次の3つをすべて満たすこと**:
   - 平均の合計が **C01の合計 − 2点** 以上（採点のぶれを1項目あたり0.3点ほど見込む）
   - どの項目の平均も **3.0以上**（1項目の大きな欠点は合計で隠さない）
   - 項目5「信頼」は **C01の点以上**（ぶれの余裕を見ない。事実・誠実さはシリーズの品質フロア。series-charter.md）
3. 具体的な数値は `README.md` の「合格の定義」に1か所だけ書く（ここには書かない）
4. 著者レビュー（第3層）の結果、合格線を超えた本で著者の指摘が多かった項目があれば、その項目の基準を厳しくする（README の更新手順）
