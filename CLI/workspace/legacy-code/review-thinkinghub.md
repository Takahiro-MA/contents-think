# レビュー1: 編集者視点（構成・キャラクター・時系列）

## A（必須修正）

### A-1: 渡辺姓衝突の解消
`渡辺健太`という人物名が Book 6（断酒本）の`渡辺翼`と姓が衝突している。shared-characters.md の NG規約（同シリーズで同姓キャラクターを登場させない）に違反。全箇所を`森健太`に変更する。

### A-2: 第1章シーン3→4の時系列矛盾
シーン3が火曜15時の設定なのに、シーン4の時刻が「同日昼休み」となっており時間が逆行している。シーン4の時刻を「同日夕方17:30。業務後」に修正する。

### A-3: 佐藤の呼称問題
メンター役の佐藤が田中さんを「田中くん」と呼んでいる箇所がある。佐藤は田中さんの直属上司ではないため「田中さん」が正しい。高橋部長のみ「田中くん」を使用する原則に統一する。

### A-4: 第1章初日デプロイの非現実性
田中さんが「最初のバグ修正で」本番デプロイしている描写は、引き継ぎ直後の描写として非現実的。「引き継ぎ翌日のバグ修正で」に変更し、リアリティを確保する。

## B（推奨修正）

### B-1: ペルソナAの「野口」姓衝突
ペルソナAの呼称として使われている「野口さん」が Book 7 の`野口達也`と姓衝突している。「安藤さん」に変更する。

### B-2: 佐藤メンタリングの場面バリエーション
4箇所の佐藤メンタリングシーンがすべて「社内カフェテリア、12:15」で固定されている。各シーンを以下のように多様化する。
- シーン1: ホワイトボード前（会議後の立ち話）
- シーン2: コーヒーマシン買い場（偶然の遭遇）
- シーン3: デスク付近（通りすがり）
- シーン4: 空き会議室（短時間の1on1）

### B-3: 第6→7章タイムジャンプの橋渡し
第6章末から第7章冒頭にかけて約1ヶ月の時間が飛んでいる。橋渡し文（田中さんの内心独白またはナレーション的地の文）を追加し、読者が迷子にならないよう補完する。

### B-4: 岡田（前任者）の再登場
第4章シーン3で、FIXMEコメントを発見した際に岡田の痕跡（コメント日付・当時の状況を推察する描写）を追加する。前任者の人間味を引き出し、「前任者を責めない」というCore Thesisを物語レベルで体現させる。

### B-5: タイトル案の検索最適化
現在の推奨タイトル案1は「物語×技術」のバランスが優れているが、検索キーワード（「レガシーコード」「JavaScript」「段階的改善」）の露出が弱い。案2をベースに副題を検索最適化する形で推奨を入れ替える。

## C（改善提案）

### C-1: 森くん（旧渡辺くん）の抵抗シーン追加
第4章シーン5で、森くんが「ファイルが増えすぎませんか？」と疑問を呈し、田中さんが一度答えに詰まってから佐藤に確認し納得する流れを追加する。チームメンバーの自然な疑問をストーリーに組み込むことで、読者の同様の疑問に先回りして答える構成にする。

### C-4: 感情アーク第3章の補強
中盤（第3章）は技術解説が密集しており、感情の山が平坦になりやすい。転換点として「confirmOrderのテスト初PASS」という小さな勝利のシーンを追加し、田中さんの達成感と読者の追体験を演出する。

### C-6: 第3章コンセプト過多への対策
第3章で学ぶ内容の項目が6つ列挙されている。項目5（依存の種類の分類）と項目6（Seam概念の導入）は内容的に連続しているため統合し、6項目→5項目に削減する。章の学習密度を下げ、初心者の離脱を防ぐ。

# レビュー2: 技術専門家視点（レガシーコード改善の正確性）

## A（必須修正）

### A-4: Express.js バージョン表記の更新
仕様書内の「Express 4.x」という表記は古い。Express 5.0 は2024年10月に正式リリース済み（WebSearch確認済み）。「Express 5.x」に全箇所変更し、5.x での変更点（エラーハンドリングの非同期対応など）にも必要に応じて言及する。

### A-5: git log hotspot コマンドの修正
掲載されている git log コマンドに空行除外フィルタが欠けており、実行結果が不正確になる。`grep -v '^$'` を追加した正しい形式に修正する。

```bash
# 修正前（不正確）
git log --format="%ae" | sort | uniq -c | sort -rn

# 修正後（空行除外を追加）
git log --format="%ae" | grep -v '^$' | sort | uniq -c | sort -rn
```

### A-6: Wrap Method 定義の精度向上
現在の定義は「既存メソッドを新しいメソッドでラップする」と簡潔すぎる。フェザーズの原典（『Working Effectively with Legacy Code』）の定義に合わせ、「既存メソッドの呼び出し前後に新しいロジックを注入する手法。既存コードを変えずに振る舞いを追加できる」と精度を上げる。

## B（推奨修正）

### A-7: Seam 分類の3分類を明記
「Seam（継ぎ目）」の説明で3分類が未記載。フェザーズの原典（WELC）に従い以下を明記する。
- **Object Seam**: オブジェクトの置き換えで振る舞いを変える継ぎ目
- **Link Seam**: リンク（import/require）の差し替えで変える継ぎ目
- **Preprocessing Seam**: ビルド時のマクロ等で変える継ぎ目（Node.jsでは主にObject/Link Seamを使用）

### B-7: Strangler Fig 説明の精度向上
現在の説明が「古いシステムを新しいシステムで置き換えていく手法」と概念的すぎる。Martin Fowler の定義（ファサードを通じて段階的に機能を移行し、最終的に旧システムを枯らす）に沿った説明に修正する。具体的には「ルーティング層にファサードを置き、エンドポイント単位で旧実装→新実装へ切り替える」という実装イメージを加える。

### B-8: 技術パターンの帰属明記
以下のパターンについて出典を明記する。
- Repository Pattern → Evans（DDD）/ Fowler（PoEAA）
- Ports & Adapters → Cockburn（Hexagonal Architecture）
- Hotspot 分析 → Tornhill（『Your Code as a Crime Scene』）

### B-9: 技術的負債の定義に原義を追加
用語リストの「技術的負債」の説明にWard Cunninghamの原義（「学習の遅延」であり、悪いコードそのものを指すのではない）を追加する。「技術的負債 = 悪いコード」という誤解を払拭し、「学習と改善のサイクルが回っていない状態」という本来の意味をペルソナCが上司に説明できる形で提示する。

## C（改善提案）

### C-9: バグ率60%減の免責注記
フィクション上の数値として記載されている「バグ率60%減」に対し、「※本書のフィクション上の数値です。実際の効果は環境により異なります」の注記を追加する。読者が社内提案に本書の数値をそのまま引用することを防ぐ。

## 総合評価

仕様書の骨格は堅固である。Core Thesis（「テストで安全網を張りながら段階的に改善する第三の道」）は明確で、マイケル・フェザーズへの敬意と実務応用の意図がバランスよく示されている。3つのペルソナ（安藤さん・浅野さん・加藤さん）のそれぞれが異なる角度から「レガシーコードの痛み」を体現しており、ターゲット設計も適切。

最優先で対応すべきは:

1. **キャラクター名の衝突解消**（渡辺→森、野口→安藤）— shared-characters.md NG規約に直結
2. **時系列矛盾の修正**（第1章シーン3→4の逆行）— 読者の信頼を損なう致命的な論理矛盾
3. **技術的正確性**（Express 5.x、git コマンド、Wrap Method/Seam の原典定義）— 技術書としての信頼性の基盤
4. **佐藤の呼称・共感表現の整合**（田中くん→田中さん、共感→提案の順序）— キャラクター設定と読者共感の両立
5. **Strangler Fig・技術的負債の定義精度**（原典に沿った説明）— ペルソナBが社内で使える説得材料の品質
