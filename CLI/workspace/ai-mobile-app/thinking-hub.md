## 1. Core Thesis（核となる主張）

**「プログラミングを一行も書けなくても、生成AIを相棒にすれば、自分の『あったらいいな』を、本当にApp Storeに並ぶアプリにできる。むずかしいのは"作ること"より、"世に出すこと"——でも、そこまで連れていってくれる地図があれば、初心者でも必ず歩ける。」**

補足: 本書は「生成AIアプリ（LLMを組み込んだアプリ）の作り方」ではありません。**生成AIを"道具"として使い、モバイルアプリそのものをゼロから作り、実際にApp Storeで公開するところまで**を、完全初心者の主人公が、弟（田中さん）に教わりながら最後まで歩く物語です。差別化の核は **"ラストワンマイル"**——「AIで動くものは作れた」人は増えても、**App Storeに公開するところまで辿り着く人は驚くほど少ない**。その谷を、物語で伴走して越えさせます。

## 2. ターゲット読者ペルソナ

### 主ペルソナ: 「作りたいものはあるけど、自分には無理だと思っている」非エンジニア
- プログラミング未経験〜ほぼ未経験。非エンジニア（事務・主婦/主夫・サービス業・企画職など）。
- 「AIでアプリが作れるらしい」と聞くが、**最初の一歩が分からず、自分には縁がないと諦めている**。
- 日常に小さな「あったらいいな」がある（家族・趣味・生活の困りごと）。
- スマホは毎日使うが、「アプリがどう作られ、どう世に出るか」は完全にブラックボックス。

### 副ペルソナ: 「AIでWebアプリは作れたが、その先が分からない」人
- ChatGPT等でちょっとした物は作れた。でも「これを人のスマホに届けるには？」で止まっている。
- 「ローカルで動く」と「App Storeに並ぶ」の間にある巨大な谷を、誰も教えてくれない。

## 3. 読者の「具体的な痛み」トップ5

1. **そもそも論が霧の中**: アプリとは／プログラミング言語とは／AIに何をどう頼めばいいのか、入り口で迷子。
2. **「作れた」止まり**: AIで動くものはできても、**公開の仕方が分からない**。Web止まり。
3. **専門用語の壁**: ビルド、署名、プロビジョニング、審査……聞き慣れない言葉で心が折れる。
4. **Mac/お金/手続きの不安**: 「iPhoneアプリってMacが要るんでしょ？」「お金かかる？」「審査落ちたら？」が漠然と怖い。
5. **「どうせ自分には無理」という諦め**: 技術書は前提知識を求めてきて、最初のページで置いていかれる。

## 6. ストーリーライン（全9章の物語アーク）

**一文要約**: 「家族のための小さなWebアプリ」が、ママ友の一言で「世界に公開するネイティブアプリ」へと昇格していく——コードを書けない結衣が、弟・田中さんと生成AIを相棒に、ゼロからApp Store公開までを歩く物語。

**技術アークの背骨（ブレ厳禁。§12正史参照）**:
1. **React の Web試作**（家族用なら、まずWebが正直な正解）
2. ママ友「使いたい」→ **公開の必然が生まれる**（他人に配る＝ストアが要る）
3. **Expo（React Native）へ移植**（同じReact、画面の部品だけ変わる＝「1つの頭・2つの体」。AIが移植を伴走）
4. **ローカル通知を足す**（アプリらしさ＋App Store審査4.2クリアのネイティブ価値）
5. **App Store公開**（Apple Developer登録・署名/プロビジョニング・App Store Connect・審査）

**感情アーク**: 「私には無理」→「えっ、できた！（ブラウザに画面）」→「家族が使ってくれる」→「人にも届けたい」→「審査落ちた…（谷）」→「公開された！知らない人がダウンロードしてくれた」（頂点）。

**期待値の正直さ**: 本書は「アプリで稼ぐ」本ではない。報酬は **「自分のアプリが世に出て、知らない誰かが使ってくれた」という達成体験**。ダウンロードは数件でも、初心者には強烈な成功体験——そこを正直に約束する。

## 10. 構成フォーマットの適応（既存テンプレからの差分）

田中さんシリーズの7部テンプレを踏襲しつつ、**完全初心者×公開**に合わせて3点を適応する。

1. **📘技術解説ボックスの"高度"を大幅に下げる**: Kiro本の📘は「Kiro固有機能」を解説したが、本書は「プログラミング言語とは」「ビルドとは」「署名とは」など**最基礎**を、結衣の素朴な疑問を起点に噛み砕く。比喩を多用。前提知識ゼロを徹底。
2. **「🛠 手順（ハンズオン）」型を第一級セクションとして新規追加**: App Store公開はGUIクリック手順主体で、純粋な物語では再現性が出ない。**物語で枠付け（田中が画面を指して説明）＋ 🛠 手順ブロックで再現可能なステップ**のハイブリッド。特に第8・9章で中心。
3. **図版/スクショを既刊より多めに（ただし更新前提）**: 公開プロセスは画面付きが圧倒的に分かりやすい。一方でApp Store Connect等のUIは陳腐化が速いので、**原理＋要所スクショ＋「画面は変わりうる」断り**で書く。クリック手順の細密化はしすぎない。

## 11. 各章シーン分解（詳細型）

### 第1章: お手伝い、続かない

**シーン1-1：破綻した紙のシール台帳**
- **場所・時間帯:** 森田家のリビング、日曜の午後
- **登場人物:** 結衣、田中、さくら、はると
- **何が起きるか:** お手伝いシールの台帳をめぐって、さくらとはるとが「貼った/貼ってない」で揉めています。結衣はため息まじりに「毎回これなのよ」と、遊びに来ていた弟の田中にこぼします。紙の台帳はぐちゃぐちゃで、誰が何をしたか誰も正確に分からない。結衣は「アプリとかにできたらいいんだろうけど、私には無理よね」と、半分あきらめ顔でつぶやきます。
- **主人公の内心・感情:** 「便利にしたい気持ちはある。でも"アプリを作る"なんて、自分の人生とは別世界の話」という諦め。
- **IT比喩:** 紙の台帳＝手作業の限界（情報が一元化されず、すぐ食い違う）。

**シーン1-2：「それ、アプリにできるかもよ」**
- **場所・時間帯:** 同上、続き
- **登場人物:** 結衣、田中
- **何が起きるか:** 田中が「姉ちゃん、それ、いまならアプリにできるよ。しかも、コードを書けなくても」と言います。結衣は「いやいや、プログラミングなんて無理だってば」と笑い飛ばします。田中は「昔はそうだったけど、いまはAIに頼んで作る時代なんだ」と、自分が仕事でAIを使っている話を、専門用語抜きで噛み砕いて話します。
- **主人公の内心・感情:** 「弟が言うなら…でも本当に？」という、疑いと小さな好奇心。
- **IT比喩:** AI＝「作り方を知ってる職人に、言葉でお願いする」道具。

**シーン1-3：そもそも、アプリって何でできてるの**
- **場所・時間帯:** 同上、続き
- **登場人物:** 結衣、田中
- **何が起きるか:** 結衣の「そもそもアプリって何なの？プログラミング言語って？」という素朴な問いに、田中が答えます。アプリは「コンピュータへの指示書」で、その指示を書くための言葉がプログラミング言語であること。そして、その指示書を**AIが代わりに書いてくれる**ようになった、という構図を、料理のレシピにたとえて説明します。
- **主人公の内心・感情:** 「思っていたより、遠い世界じゃないのかも」と霧が少し晴れる感覚。
- **IT比喩:** プログラミング言語＝レシピを書く言葉、AI＝レシピを代筆してくれる人。

**シーン1-4：「ちょっとだけ、やってみようかな」**
- **場所・時間帯:** 同上、夕方
- **登場人物:** 結衣、田中
- **何が起きるか:** 田中が「次の週末、一緒に最初の一歩だけやってみる？ダメそうならやめればいい」と提案します。結衣は迷いつつ「…やってみたい、かも」と、はじめて前向きな言葉を口にします。田中は「いきなり完璧を目指さない。小さく動くものから、ね」と、これからの進め方をひとこと添えます。
- **主人公の内心・感情:** 不安7割・わくわく3割。「私にもできるんだろうか」。
- **IT比喩:** なし（決意のシーン）。

### 第3章: ブラウザに、画面が出た

## 12. 技術正史（全章で守る・ブレ厳禁）

執筆チームは以下を絶対の前提とする。矛盾する記述を書かないこと。**コマンド・サービス名・手順は執筆時に必ず公式ドキュメントで再照合**（UIや要件は陳腐化が速い）。

- **スタック**: Expo（React Native）。言語は JavaScript / TypeScript。**Flutter（Dart）ではない**。理由＝AIが最も得意な言語帯＋WebのReactと地続き（移植が自然）＋EASでMac不要のビルド/提出。
- **技術アークの順序**: ①React の Web試作 → ②Expo（React Native）へ移植（AI伴走、ロジック流用・UIだけ作り直し）→ ③ローカル通知 → ④App Store公開。**「WebをWebViewで包んでストアに出す」は描かない**（ガイドライン4.2でリジェクトされうる＝偽装。本書は"作り直し（移植）"で正攻法）。

- **公開の必然（モチベーション）**: 「家族用＝Webで十分」が出発点。**ママ友が"使いたい"＝他人に配る必然 → ストアが要る**、で初めてネイティブ＆公開が正当化される。作者都合の公開にしない。
- **ネイティブ化の三つの価値（同時に立つ）**: ①配れる（ストアで他人へ）②ホーム画面アイコン＋タップで開く ③ローカル通知＝アプリらしさ（審査4.2クリアのネイティブ価値）。

- **Mac不要**: EAS（Expoのクラウドサービス）でiOSビルド・App Store提出ができる＝**Macが無くても公開まで行ける**（初心者の物理的ハードルを下げる要）。ただし Apple Developer Program 登録（有料）は必要。

- **AI主導の高度**: 目的は「読めて・指示できて・検証できる」レベル（手で書ける、ではない）。中身を完全ブラックボックスにしない（田中さんシリーズの「動くけど説明できる」の初心者版）。
