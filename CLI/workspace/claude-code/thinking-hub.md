## 1. Core Thesis（核となる主張）

**「AIコーディングアシスタントは"便利なツール"ではない。開発者の思考プロセスそのものを拡張する"もう一人の自分"である。CLIから対話するClaude Codeは、その本質を最も純粋に体験できる入り口だ。」**

補足: 本書の主張は「Claude Codeの操作マニュアル」ではない。「AIと一緒にコードを書く」とはどういうことか——コードベースの探索、設計の壁打ち、バグの追跡、テストの自動生成、レガシーコードのリファクタリング、CLAUDE.mdによるプロジェクトルールの言語化——を田中さんの成長物語を通じて読者に追体験させることが目的である。

大切なのは「AIに丸投げする」ことではなく「AIと協働する」こと。自分の頭で設計し、AIに実装を手伝ってもらい、AIの出力を自分の目でレビューする。この「人間×AI」の協働ループを回せるエンジニアこそが、AI駆動開発時代に最も価値を発揮する——それが本書の核心メッセージである。

## 3. 読者の「具体的な痛み」トップ5

### 痛み1: 「AIが書いたコードの全体像が見えない」問題
> CursorやCopilotでコードを生成させたが、ファイル単位の補完に留まる。プロジェクト全体のアーキテクチャを理解した上で整合性のあるコードを書いてくれるAIツールが欲しい。複数ファイルにまたがる変更をお願いすると、あちこちで不整合が起きて手動修正が大変。結局、自分で書いた方が早いのではと思ってしまう。

### 痛み2: 「既存の大規模コードベースにAIをどう適用すればいいか分からない」壁
> AI駆動開発の記事やチュートリアルは、ゼロからプロジェクトを作る例ばかり。自分の現場には10万行超のレガシーコードがあり、そこにAIをどう投入すればいいのか見当がつかない。新規プロジェクトならともかく、既存コードベースの理解・改善にAIを使う具体的な方法論がどこにもない。

### 痛み3: 「AIに自分たちのコーディング規約を守らせられない」苛立ち
> チームにはコーディング規約、命名規則、アーキテクチャの方針がある。AIが生成するコードはそれらを無視する。毎回プロンプトで説明するのは面倒だし、説明しても守られないことが多い。プロジェクト固有のルールをAIに「覚えさせる」方法があれば使いたい。

### 痛み4: 「AIツールが多すぎて、どれをどう使い分ければいいか分からない」混乱
> Cursor、GitHub Copilot、Cline、Windsurf、Claude Code、OpenAI Codex...。毎月のように新しいAIコーディングツールが出てくる。それぞれの違いも分からない。全部試す時間もない。「結局どれを使えばいいのか」という問いに答えてくれる人がいない。

### 痛み5: 「AIに頼りすぎてエンジニアとしての実力が落ちるのでは」という恐怖
> AIにコードを書かせたら、自分のプログラミング力は落ちるのでは。設計力が衰えるのでは。後輩がAIに丸投げして基礎力がつかないのを見て心配になる。「AIを使うべきところ」と「自分で書くべきところ」の線引きが分からない。

### 第1章: はじめてのAI駆動開発 —— 新規プロジェクトで「相棒」と出会う

**田中さんの課題:**
高橋部長から「社内の工数管理ツールのプロトタイプを2週間で作ってほしい」と頼まれた田中。Spring BootでREST APIを作り、簡単なフロントエンドも含めてデモできる状態にする必要がある。設計からテストまで1人でこなすには時間が足りない。以前GitHub Copilotを試したが、ファイル単位の補完では全体の設計を手伝ってくれず期待外れだった。

**学ぶ内容:**
1. AI駆動開発の全体像 —— 「補完ツール」と「エージェント」の違い
2. Claude Codeとは何か —— CLIベースのAIコーディングエージェントの基本概念
3. AIとの対話で設計を固める —— 「こういうAPIが欲しい」から始まるプロトタイピング
4. コード生成→レビュー→修正のAI協働ループを体感する

**ストーリーライン:**
高橋部長から「チームの工数管理を効率化する社内ツールのプロトタイプ」を2週間で作るよう任された田中。設計をどこから始めるか迷っていると、佐藤先輩が「Claude Code、使ってみない？ 新しいものを作るときこそ試しやすいよ」と声をかけてくれる。翌朝、ターミナルでClaude Codeを起動し、「Spring Bootで工数管理APIを作りたい。エンドポイント設計から一緒に考えて」と対話を始める。AIがAPI設計を提案し、田中がレビューし、方向を修正する。半日で基本的なCRUD APIが動き、田中は目を見張る。「これは補完ツールじゃない。設計から一緒に考えてくれる"もう一人のエンジニア"だ」。

**実践ワーク:**
- [ ] Claude Codeをインストールし、ターミナルで起動してみる
- [ ] 「○○を作りたい。設計から一緒に考えて」とAIに対話を持ちかけてみる
- [ ] AIが提案したコードを自分でレビューし、修正点を1つ見つける

### 第2章: 「うちのルール」をAIに教える —— CLAUDE.mdとSkills

**田中さんの課題:**
Claude Codeとのプロトタイピングに手応えを感じた田中。だが、書いたコードをPRに出したところ、レビューで複数の指摘が入る。「変数名がうちの命名規則と違う」「例外処理はCustomExceptionを使うルール」「Repositoryの戻り値はOptionalで統一」。Claude Codeが書くコードは動くが、チームの規約を知らない。毎回プロンプトで規約を説明するのは面倒すぎる。

**学ぶ内容:**
1. CLAUDE.mdの概念 —— プロジェクトルールをAIに「記憶」させる仕組み
2. 効果的なCLAUDE.mdの書き方（コーディング規約、アーキテクチャ方針、禁止事項）
3. チーム共有のCLAUDE.mdとローカルのCLAUDE.mdの使い分け
4. 「ルールを守ったコード生成」を実現するプロジェクト設定の実践
5. カスタムスラッシュコマンド（Skills）の作成と活用 —— /.claude/commands/にMarkdownファイルを置くだけで独自のスラッシュコマンドを登録できる仕組み。プロジェクトレベル（チーム共有）とユーザーレベル（個人用）の使い分け

**ストーリーライン:**
プロトタイプのPRにレビューコメントが付く。「うちの命名規則と違う」「例外処理が統一されていない」。田中は落ち込むが、佐藤先輩が「CLAUDE.mdって知ってる？」と切り出す。佐藤先輩のプロジェクトのCLAUDE.mdを見せてもらうと、コーディング規約、アーキテクチャの方針、やってはいけないことが明文化されている。「これを書いておけば、Claude Codeは毎回読んでくれる。チームの新人にオンボーディング資料を渡すのと同じ感覚」と佐藤先輩。田中はプロトタイプ用のCLAUDE.mdを書き始め、Claude Codeの出力がチームの規約に沿ったものに変わっていく。さらにカスタムスラッシュコマンド（Skills）も作成し、レビューやテスト生成の定型作業を自動化する。

**実践ワーク:**
- [ ] 自分のプロジェクトのコーディング規約・方針を箇条書きで10項目書き出す
- [ ] CLAUDE.mdファイルを作成し、書き出した規約を記載する
- [ ] CLAUDE.mdありとなしで同じ依頼をClaude Codeに出し、出力の違いを比較する

### 第3章: 設計を磨き、テストで守る —— Plan modeとAI協働テスト

**田中さんの課題:**
プロトタイプは好評で、河野PMから「このまま本番運用に耐えるレベルに引き上げてほしい」と言われた。だがプロトタイプにはテストがない。設計も「とりあえず動く」レベルで、本番を想定したアーキテクチャになっていない。プロトタイプから本番品質への引き上げ——設計の見直しとテスト整備を効率的に進める必要がある。

**学ぶ内容:**
1. Plan modeを使った設計の見直し —— 「いきなり書く」のではなく「まず計画を立てる」
2. 既存コードのテスト作成をClaude Codeに依頼する実践的な方法
3. 「このメソッドのテストを書いて。正常系3、異常系2、境界値1で」—— 具体的な指示の出し方
4. AI生成テストの品質チェック —— カバレッジだけでなく「意図」を確認する
5. TDD（テスト駆動開発）とAIの組み合わせ —— 先にテストを書かせてから実装する

**ストーリーライン:**

### 第4章: 10万行のコードの海で溺れる —— 既存コードベースへの挑戦

## 8. Counter Arguments（想定反論と回答）5つ

### 反論1: 「Claude Code専用の本なんて、ツールが変わったら価値がなくなるのでは？」

**回答:**
本書はClaude Codeの操作マニュアルではない。「既存コードベースの探索手法」「CLAUDE.mdによるルールの言語化」「Plan modeによる設計思考」「Subagentによる並列作業の設計」「AI生成コードのレビュー観点」——これらはClaude Code固有の知識ではなく、AI駆動開発の普遍的なスキルである。ツールのUIやコマンドは変わっても、「AIに文脈を与える」「計画を立ててから実行する」「出力を自分で判断する」という原則は変わらない。むしろCLAUDE.mdの考え方は、Cursor Rules（.cursorrules）やCopilot Instructions（.github/copilot-instructions.md）にも通じるものであり、本書で学ぶ思考法はツール横断的に活きる。

### 反論2: 「AI駆動開発の本はすでにたくさん出ているのでは？」

**回答:**
2025〜2026年にかけて「AI駆動開発完全入門」（インプレス）、「Claude CodeによるAI駆動開発入門」（技術評論社）、「AI駆動開発の教科書」（リックテレコム）等が出版されている。いずれもハンズオン形式の技術書であり、「ゼロからアプリを作る」チュートリアルが中心。本書は「既存の大規模コードベースにAIをどう適用するか」という実務で最も頻出する課題に焦点を当て、しかも物語形式で「感情面の壁（不安・焦り・抵抗感）」も含めて描く。技術書を100ページ読むより、田中さんの失敗と成長を通じて「自分もやってみよう」と思える——それが本書の独自価値である。

### 反論3: 「物語形式は回りくどい。コマンドリファレンスだけ端的に教えてほしい」

**回答:**
コマンドリファレンスはClaude Codeの公式ドキュメント（code.claude.com/docs）に充実している。しかし多くの開発者は「コマンドは知っているが、どの場面で使えばいいか分からない」「AIとの協働の"勘所"が掴めない」状態にある。物語形式は、読者の「感情」（既存コードへの不安、AI生成コードへの不信、チーム導入の壁）に寄り添い、「自分の現場でもこうすればいいのか」という具体的なイメージを与える。田中さんシリーズの既刊が証明しているように、物語形式には技術書にない「読了率の高さ」と「行動変容力」がある。

### 反論4: 「CLIツールなんて使いにくい。CursorやCopilotの方が便利では？」

**回答:**
本書はCLI至上主義を唱えるものではない。第8章で明確に「Cursorは複雑なリファクタに強い」「CopilotはIDEでの日常的な補完に便利」「Claude CodeはCLIベースで深い対話と自律的な作業に適している」とツールの使い分けを解説する。大切なのは「どのツールが最強か」ではなく「自分の開発ワークフローにどう組み込むか」。本書がClaude Codeを主軸に据えるのは、CLIベースの対話型エージェントが「AIとの協働」の本質——文脈の共有、計画の立案、段階的な実行——を最も純粋に体験できる形態だからである。CursorやWindsurf等のGUIツールを使う読者にとっても、本書で学ぶ「AI協働の原則」はそのまま応用できる。

### 反論5: 「セキュリティが心配。コードをAIに見せて大丈夫なのか？」

**回答:**
これは極めて重要な懸念であり、本書は第7章で正面から扱う。Claude Codeはローカルで動作し、ユーザーが明示的に許可した操作のみ実行する。ただし入力内容はAnthropicのAPIに送信されるため、機密情報の取り扱いには注意が必要。本書ではチーム向けの「AI活用セキュリティガイドライン」の作り方を具体的に示し、「入力してはいけない情報」「社内承認プロセス」「ログの管理方法」を整備する実践例を描く。セキュリティを理由にAI活用を全面禁止するのではなく、「適切なルールの下で活用する」という現実的なアプローチを提案する。

   - 2026年2月時点で、AI駆動開発をテーマにした書籍はすべて「ハンズオン形式」か「教科書形式」。物語でAI駆動開発を学ぶ書籍はブルーオーシャン。「技術書は挫折するが、物語なら最後まで読める」読者層を獲得できる

2. **「既存コードベースへのAI適用」にフォーカスしている**
   - 競合書籍の大半は「ゼロからアプリを作る」チュートリアル。しかし実務で最も頻出する課題は「10万行の既存コードをどう理解・改善するか」。この切り口の書籍はほぼない

3. **CLAUDE.mdによる「ルールの言語化」を物語で体験できる**
   - CLAUDE.mdの書き方は公式ドキュメントにあるが、「なぜそれが必要か」「チームでどう運用するか」を実感レベルで理解できる教材はない。田中さんがレビューで指摘される→CLAUDE.mdを書く→出力が変わる、という体験を追体験できる

4. **CLIエージェントの「協働の本質」を描いている**
   - GUI系ツール（Cursor, Copilot）では「補完を受け入れる/拒否する」の二択になりがち。CLIベースの対話型エージェントは「計画を立てる→段階的に実行する→レビューする」という協働のループを最も明確に体験できる。この「協働の原則」はツール横断的に応用できる

5. **「田中さんシリーズ」のブランド力とクロスセル**
   - 既刊9冊＋新刊3冊企画中のシリーズ。「AI仕事術」本の読者を「AI駆動開発」へ自然に誘導できる。逆に本書からシリーズに入る技術志向の読者も獲得できる
