# 人間レビュー指摘の抽象化 — LLM自動レビューへの吸収可能性の精査

作成: 2026-07-07 / 対象: 全書籍の著者レビュー記録（約120件）
ソース: obsidian epub 24件・codex epub 31件・linux Phase5 20件・codex thinking-hub 1A 8件＋ChatGPT技術19件・kiro 著者判断12件＋epub復元29件

## 結論（3行）

1. 人間指摘の**約7割はパターン化可能**で、うち半分は既に自動レビューに吸収済み（フィードバックループは機能している）
2. 残り半分（約35件相当）は**5つの新観点＋2つの仕組み**で自動化できる
3. **約3割は人間にしか出せない**が、その大半も「一回性の修正」でなく「美学ルール」として蓄積すれば次書籍からは自動検査できる

## 1. 分類と判定

### ✅ 既に自動レビューへ吸収済み（レビューコマンドに痕跡が明確なもの）

| 人間指摘（初出） | 現在の自動レビュー観点 |
|---|---|
| ネガフィルム比喩・ナプキンメモ・定期面談（obsidian #8,10,17,20） | review-book: 比喩の品質チェック（年齢/世代/論理/キャラ/現代性） |
| 5分検索・30分問題・20分15件（obsidian #11,13 / linux #9） | review-book: 時間感覚・現実性／問題設定の説得力 |
| 未刊行書籍の紹介（obsidian #2,22 / codex #3） | review-book: 書籍情報の正確性（book-status照合） |
| 00→01導線（obsidian #1） | review-book: 導線チェック |
| 用語の無説明初出（linux #5,16 / obsidian #14） | review-book: 技術用語の初出チェック（ジュニア） |
| 操作結果が見えない（obsidian #3） | review-book: 操作結果の可視化 |
| AI描写の陳腐化（linux #18） | review-book: AI関連記述の時代適合性 |
| 口調不統一（linux #10 / codex #11） | review-book: 口調の一貫性（部分的。※下記ギャップ参照） |

### 🔧 抽象化して自動化可能（未吸収・今回の提案対象）

**G1. 前提知識の突合**（codex #2,6,18,25 / obsidian #12 / kiro 99129a2 — 約10件）
00で宣言した必須/推奨知識と、本文が無補足で使う概念のギャップ。
→ ジュニアレビューに「**00の前提知識宣言を読み、それを超える概念が補足なしで出ていないか突合**」を追加。

**G2. 設定の因果監査**（codex #7,9,15,17,21,22,23 / kiro 7f37f57,24a5ee8,7afb16c — 約12件）
人間指摘の最大の未吸収クラスタ。「宮本が傍観者で登場（同じ境遇のはず）」「3ヶ月放置の説明なし」「規約を知るレビュアーがいるなら前提と矛盾」「振り返りに未実施項目」「エンジニアがlintを安心して飛ばす」。
→ 編集者レビューに「**設定の因果監査**: 登場人物の行動に職業的合理性があるか／空白期間・環境（本番か否か）が説明されているか／前提設定と矛盾する便利キャラ・便利展開がないか」を追加。

**G3. 機能・概念の初出台帳**（codex #23「execが初出扱い」,#30 / kiro 4c64d20 — 約5件）
→ check-consistency に「**初出マトリクス**: 主要機能・概念の初出章を一覧化し、後章で初発見扱いされていないか／初出章に説明義務が果たされているか」を追加（機械的に作れる）。

**G4. 技術記述の3点セット**（codex #10,12,14,29,30 / 1A 9-1〜9-13 — 約15件）
人間とChatGPT監査が繰り返し見つけたのは：デフォルト挙動の明記漏れ／状態のライフサイクル（セッションで何が引き継がれ、何が再起動必要か）／変動しやすい固有名（モデル名・価格）の執筆時点注記漏れ。
→ シニアレビューに3項目として明文化。

**G5. 口癖・内心の場面整合**（codex #5,24 / kiro ca37939,1f83cf2 — 約6件）
「口癖の分散」はチェック済みだが「場面に馴染んでいるか」が未チェック。緊迫場面に取ってつけた口癖、当然の相手への「本気だ」。
→ 編集者レビューの口癖チェックを「分散＋**場面の感情と整合しているか（取ってつけ感）**」に拡張。

**G6. シリーズ標準装備の検査**（obsidian #24 / codex #31 / 1A #1,2 — 約5件）
巻末付録の有無・タイトルフォーマット「ストーリーで学ぶ〇〇入門」・統一価格（Kindle 980円/PB 2,970円）。
→ thinking-hubテンプレ§4・§10に固定値として記載＋ review-thinkinghub の構造チェックに追加。

### 🤝 仕組みとして制度化すべきもの（単発観点でなくプロセス）

**P1. 美学ルールの収穫所（author-style-rules.md）**
人間指摘の約3割は「好み・美学」だが、**繰り返し性がある**: ポンコツ/ボンクラ等の負の像禁止・「いい指摘ですね」型の褒め台詞禁止・「第N章」メタ参照禁止・あとがきは感謝で締め蛇足禁止・匂わせ次回予告禁止・「ペルソナ」を読者向け文で使わない。
→ これらを1ファイルに収穫し、write-chapter と review-book が参照する。**今後の著者指摘のうち「二度目がありそうなもの」は修正と同時にこのファイルへ追記する運用**（失敗の資産化の執筆版）。

**P2. 独立モデルによる技術監査の正式工程化**
実績が2回ある: codex本のChatGPT監査（19件、うちCRITICAL 5件）、kiro本のCodexレビュー監査（b5ea744で全面修正）。同一モデルの3視点レビューは思い込みを共有するが、**別モデルは公式照合で別の穴を見つけた**。
→ Phase 3 を「Claude 3視点 → 別モデル技術監査（ChatGPT/Codex等に公式URL付きで検証させる）」の2段構成として book-writing-framework に明記。

### 👤 人間にしか出せないもの（自動化を試みない）

- **戦略・方向性の判断**: kiro著者判断サマリの全12件（第4章主軸をSubagentsへ・痛み5の差し替え・キャラ変更・タイトル方針）。これは「レビュー」でなく「編集会議」であり、自動化の対象外
- **肌感の閾値**: 「ブログ3本は少ない」（obsidian #18）のような量的な違和感
- **採否の最終判断**: 自動レビューのA/B/C指摘に対するGO/NO-GO（kiroの「著者判断サマリ」形式が最良実践。自動レビューは提案までで、処分は人間）

## 2. 効果の見積もり

次の書籍で同種の指摘が出た場合の先回り率（過去指摘の分類ベース）:

| 区分 | 件数比 | 対応 |
|---|---|---|
| 既吸収（現行コマンドで検出可能） | 約35% | 維持 |
| 今回の G1〜G6 追加で検出可能 | 約30% | 本提案 |
| P1美学ルール（収穫後に検出可能） | 約15% | 本提案＋継続運用 |
| 人間必須（戦略・肌感・採否） | 約20% | 著者レビューを「判断サマリ形式」に集中させ軽量化 |

＝ 実装後、**著者レビューの負荷を「約120件の指摘出し」から「戦略判断＋自動指摘の採否」に圧縮**できる見込み。
